# Доступ администратора к 3x-ui

Скопируйте `admin.example.json` в `admin.local.json` рядом со скриптом и заполните адрес VPS, HTTPS-адрес панели и проверенный ED25519-отпечаток SSH. Файл `admin.local.json` исключён из Git. Адрес `192.0.2.10` в примере относится к диапазону для документации.

Запустите `Open-3xui.cmd`. В поле `SshUser` укажите существующего SSH-пользователя Linux. Можно также выполнить команду из PowerShell.

```powershell
.\Open-3xui.cmd -SshUser panel-operator
```

OpenSSH запрашивает пароль либо парольную фразу ключа в отдельном окне. Учетные данные должны быть настроены на сервере и компьютере администратора. При первом подключении сравните показанный OpenSSH отпечаток с доверенным источником. Скрипт выводит ожидаемый отпечаток из локального файла, фактическую проверку известного ключа выполняет OpenSSH через `known_hosts`.

После открытия проброса `127.0.0.1:47549` → серверный `127.0.0.1:47548` запускается отдельный профиль Chrome. Chrome сохраняет исходное имя HTTPS-узла при локальном сопоставлении адреса. Оставьте SSH-окно открытым на время работы с панелью. В веб-панели потребуется отдельный вход.

При сбое окно CMD сохраняет сообщение. Скрипт печатает последние строки журнала SSH и путь к полному журналу в `%LOCALAPPDATA%\3xui-admin-tunnel`. Сеансовые cookies Chrome хранятся в этом отдельном пользовательском профиле браузера. Журналы и профиль браузера относятся к данным компьютера администратора.

Порядок аутентификации и обработки учетных данных описан в [authentication.md](../../docs/authentication.md). Для ошибки `255` используйте [диагностику SSH](../../docs/operations.md#если-ssh-завершился-с-кодом-255).
