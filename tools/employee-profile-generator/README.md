# Выдача Windows-профилей

1. Создайте клиента в inbound панели 3x-ui и скопируйте его VLESS-ссылку.
2. Запустите `Create-Profile.cmd` и введите имя файла латиницей. Пример имени — `employee01`.
3. Если текстового профиля в буфере нет, вставьте ссылку в появившийся запрос.
4. Передайте сотруднику созданный `profiles/employee01.json`. Сотрудник импортирует его как Custom с ядром Xray в v2rayN и включает системный прокси.

Имя файла служит для учета. UUID и параметры подключения берутся из входной ссылки. Отдельный клиент в 3x-ui дает отдельную учетную запись VPN. Полный JSON включает маршруты и DNS из `employee-template.json`.

```powershell
.\New-EmployeeProfile.ps1 -Name employee01 -SourceFile C:\profiles\source.json
```

Входом может быть полный клиентский JSON с одним VLESS-выходом `proxy`. Для прямой VLESS-ссылки поддерживается XHTTP + REALITY, включая JSON `extra`, `x_padding_bytes` и флаг совместимости `support-x25519mlkem768`. При наличии локального Xray выполняется проверка `run -test`. Для другого расположения ядра передайте `-XrayPath`. Без ядра скрипт сообщает об отсутствии проверки Xray.

Генератор версии `2026-11-25.5` содержит исправления определения своей папки в Windows PowerShell, пустого буфера обмена и расширенных параметров ссылок 3x-ui. Повторное имя вызывает ошибку, чтобы сохранить ранее выданный файл. Генератор завершает запись через временный файл и убирает его при ошибке.

Корпоративная зона разрешается системным DNS Windows. Для внутренних ресурсов необходим корпоративный DNS и маршрут до сервиса. Приложения с собственным DoH и трафик программ, игнорирующих системный прокси, требуют отдельной проверки.

Готовые профили содержат действующий UUID в открытом виде и находятся в исключенной из Git папке `profiles/`. Передавайте профиль конкретному сотруднику. Срок действия и отзыв задаются в панели 3x-ui. Общие правила изменяются в шаблоне и применяются при следующем создании JSON.
