# Историческая цепочка RU → Reykjavík

## Снимок Xray и импорты 3x-ui

Снимок содержит два входа XHTTP + REALITY и три штатных выхода. Импорты 3x-ui сохранены отдельно от сгенерированного runtime-конфига Xray.

| Элемент | Роль в снимке |
| --- | --- |
| `in-41686-tcp` / `RU-entry` | Вход на TCP 41686. После служебных фильтров направляется в `to-reykjavik`. |
| `in-34750-tcp` / `mob` | Отдельный мобильный вход. В найденном снимке собственное правило отправки в `to-reykjavik` отсутствует. |
| `to-reykjavik` | Исходящее подключение VLESS + XHTTP + REALITY к узлу Reykjavík. |
| `api`, `direct`, `blocked` | Служебный API, прямой выход по умолчанию и блокировка. Правила для частных IP и BitTorrent расположены выше правила входа 41686. |

Шаблоны в `configs/ru-reykjavik/` сохраняют структуру снимка и форматы экспортов. Файл `ru-current-xray.example.json` предназначен для разбора runtime-конфига. `ru-entry-3xui.example.json` и `ru-mobile-3xui.example.json` воспроизводят формат импорта 3x-ui. Для загрузки используйте исходный экспорт с действующими значениями или заполненный шаблон. Снимок датируется ноябрём и сам по себе не устанавливает текущую конфигурацию панели.

## Что менялось

- Для российского входа проверялся маршрут `to-reykjavik`. В одной из проверок выход отвечал с задержкой около 528 мс.
- Отдельный `mob-public` и правила RU/direct и корпоративного портала тестировались и затем откатывались. При откате вернули маршрут PC:41686 → `to-reykjavik`, мобильный вход 34750 сохранили. Побайтовое совпадение всей базы панели с прежним состоянием не подтверждено.
- Старый мобильный QR сохранён как исторический материал. Для рабочего телефона получите ссылку заново из нужного inbound в панели и проверьте Wi-Fi и мобильную сеть отдельно.
- Полного серверного экспорта Reykjavík среди найденных файлов нет. В снимке RU есть соответствующий outbound, по которому можно сопоставить параметры с inbound на Reykjavík.

## Проект пилота MikroTik

По экспорту от 11 ноября рассматривалась схема, в которой MikroTik отправляет выбранный TCP/UDP-трафик по локальному WireGuard на RU-VM. RU-VM направляет выбранные российские назначения напрямую, прочий трафик — через VLESS в Reykjavík. Корпоративный DNS и внутренние маршруты сохраняются. Пилот предполагалось начать с IT-сегментов с отдельной таблицей маршрутизации и возможностью возврата на WAN. Полный обзор и исходный экспорт доступны в `local/mikrotik/`.

Проект учитывал два WAN, симметрию ответов, Forward ACL, действующую схему AWG и корпоративные префиксы. Проверок внедрения или нагрузки в найденных материалах нет.
