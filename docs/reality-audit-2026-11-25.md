# Аудит REALITY от 25 ноября 2026

Проверка выполнена для самостоятельного VLESS VPN сотрудников. Факты о сервере получены из команд пользователя и отчета `tools/audit-reality.py`. Клиентские запросы выполнены с доступного Windows-ПК. Адрес VPS, персональные UUID, ключи и путь администрирования сохраняются в локальных материалах.

Отчет показал пустые `minClientVer` и `maxClientVer`, отсутствие явного `maxTimeDiff`, включенный sniffing для `http`, `tls`, `quic`. Значения по умолчанию необходимо соотносить с версией ядра. Полный экспорт VPS в Git не добавлялся. [Серверный пример на основе проверенных полей](../configs/server/reality-inbound.example.json)

1. **TLS с VPS до цели**

Проверены `telia.lt:443` и `www.telia.lt:443`. Оба узла согласовали TLS 1.3, ALPN `h2` и сертификат для соответствующего имени. OpenSSL вернул `Verify return code: 0 (ok)`. Сертификаты на момент теста находились в пределах срока действия.

```bash
timeout 20 openssl s_client -connect telia.lt:443 -servername telia.lt -tls1_3 -alpn h2 -verify_hostname telia.lt -verify_return_error </dev/null
```

2. **Обычный HTTPS к входному адресу VPS**

Для повторения на Windows замените `192.0.2.10` фактическим адресом VPS и выключите VPN на тестовом подключении.

```powershell
curl.exe --noproxy "*" --ssl-revoke-best-effort --resolve "telia.lt:443:192.0.2.10" --resolve "www.telia.lt:443:192.0.2.10" --connect-timeout 10 --max-time 25 --max-redirs 5 -I -L -v "https://telia.lt/"
```

Через входной адрес получена последовательность `302` на `https://www.telia.lt/`, затем `301` на `/privatiems`, затем `200 OK`. Windows curl предлагал HTTP/1.1 и согласовал его. HTTP-перенаправление относится к ответу сайта. Оно само по себе не устанавливает, распознается ли VPN. Первоначальную гипотезу о необходимости смены цели из-за редиректа уточнили после прохождения всей цепочки.

Обычная проверка Schannel сначала вернула `CRYPT_E_REVOCATION_OFFLINE`. Повтор с `--ssl-revoke-best-effort` сохранил проверку доверия и имени, разрешив недоступность сведений об отзыве. Статус отзыва в этих Windows-тестах остался непроверенным. Параметр использовался для отдельных диагностических запросов. [Документация curl](https://curl.se/docs/manpage.html#--ssl-revoke-best-effort)

3. **Запрос с VPN-аутентификацией**

Создан временный экземпляр клиентского конфига на `127.0.0.1:41088`. Загрузка `/privatiems` через профиль завершилась `200 OK`, объем составил 2 365 586 байт. Дополнительный HEAD-запрос с принудительным направлением всего тестового трафика в VLESS `proxy` также получил `200 OK`. Это подтвердило работу UUID и ShortID проверенного профиля вместе с REALITY и XHTTP. Временные процессы остановлены и файлы удалены.

Эти измерения подтверждают работу на выбранном подключении и в указанный момент. Протокольный отпечаток, ограничения по IP и особенности других операторов оцениваются отдельными тестами. Обновление серверного ядра, смена цели, развертывание моста и проверка нового Android-клиента остаются отдельными работами. [Описание REALITY](https://github.com/XTLS/REALITY/blob/main/README.en.md)
